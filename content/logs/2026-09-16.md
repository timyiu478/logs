#### Async Rust

##### Task Lifecycle

* `.abort()` sends a cancellation signal to the task. The task does not stop immediately — it is cancelled at the next `.await` point. 
* Async cleanup after an `.await` is not guaranteed on cancellation. Put mandatory cleanup in `Drop` (synchronous) or use `CancellationToken` to intercept the shutdown signal and run async teardown before the task exits.

#### Dynamic Programming: LC-2826. Sorting Three Groups

* **Key Idea:** 
  * The minimum number of operations to make the array non-decreasing = `nums.length` - `length of Longest Non-Decreasing Subsequence (LIS)`.
  * Since numbers are strictly in `{1, 2, 3}`, we only need to track the max LIS length ending at values 1, 2, and 3 ($O(N)$ time, $O(1)$ space).

* **State Definition:**
  * `dp[1]`: Max LIS length ending with value 1
  * `dp[2]`: Max LIS length ending with value 2
  * `dp[3]`: Max LIS length ending with value 3

* **Transitions (for each number `x` in `nums`):**
  * When processing `x`, it can extend any valid subsequence ending in a value `<= x`:
  * If `x == 1`: `dp[1] = dp[1] + 1`
  * If `x == 2`: `dp[2] = max(dp[1], dp[2]) + 1`
  * If `x == 3`: `dp[3] = max(dp[1], dp[2], dp[3]) + 1`

* **Final Result:**
  * `nums.length - max(dp[1], dp[2], dp[3])`

#### Heap: LC-632. Smallest Range Covering Elements from K Lists

* Core Intuitions:
    * To cover at least one element from every list with the smallest range `[a, b]`, we start with the first element of each of the `k` sorted lists.
    *  By picking the first element of every list, we form the absolute leftmost valid candidate window `[a, b]` 
    * To minimize `(b - a)`, we must greedily advance the pointer of the **smallest element currently selected** (`a`), hoping to increase it and
shrink the range.
    * Advancing any element other than the minimum would only increase `b` without increasing `a`, widening the range.
