#### Async Rust

* High-I/O, low-CPU workloads where Async Rust yields maximum efficiency: high-I/O, low-CPU workloads where Async Rust yields maximum efficiency

* CPU Heavy Tasks: Cryptographic Operations (Encryption, Authentication), Compression, Data Transformations

* Separate thread pools prevent CPU-bound tasks from starving async I/O tasks. The Tokio worker threads never see that long CPU task in their run queue, so they continue picking up and driving async I/O futures without delay.
    * Why work stealing isn't enough: Work stealing only helps distribute idle tasks. If all worker threads concurrently pick up CPU-bound tasks, the entire runtime stalls, and no stealing can occur.

* Multiple runtimes in the same process are a valid pattern for resource isolation. Ingress and housekeeping workloads with fundamentally different resource profiles benefit from separate thread pools rather than competing on a shared executor.
    * e.g. Ingress runtime: 4 blocking threads, Housekeeping runtime: 32 blocking threads
