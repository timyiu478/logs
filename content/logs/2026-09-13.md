#### Heap: LC-1834. Single-Threaded CPU

##### 1. Pre-sorting by `enqueueTime`

* **Why:** Tasks arrive chronologically. Sorting by `enqueueTime` enables a linear scan O(N) to enqueue tasks exactly as they become available on the timeline.

##### 2. Available Task Pool (Min-Heap)

* **What it stores:** All tasks that have arrived (`enqueueTime <= now`) but have not yet been processed.
* **Ordering Priority:**
  1. `processingTime` (shortest job first)
  2. Original `index` (for storing the order in which the CPU will process the tasks)

##### 3. Timeline Management

The simulation tracks current time using a variable `now`, which advances in two scenarios:

1. **CPU processes a task (`q` is non-empty):**
   * Pop top task `(process_time, idx)` from heap.
   * Advance time: `now += process_time`
   * **Enqueue new arrivals:** Add all remaining tasks where `enqueueTime <= now`.

2. **CPU is idle (`q` is empty):**
   * Jump time forward to the next task's arrival: `now = tasks[i][0]` (where `[0]` is `enqueueTime`).
   * Push that task into the heap to restart processing.
