#### Lessons in Building Async Telemetry Broker in Rust using Tokio

1. **Stream-to-Frame Decoding**: Use [`tokio_util::codec`](https://tokio.rs/tokio/tutorial/framing) to convert raw, unstructured TCP byte streams into discrete binary frame objects.
2. **Decoupled High-Speed Ingestion**: Use a [`tokio::sync::broadcast`](https://docs.rs/tokio/latest/tokio/sync/broadcast/index.html) channel to separate socket read loops from slow downstream consumers.
   * *Lagging Mechanics*: When a worker falls behind channel capacity, its cursor is automatically advanced to the oldest retained message, dropping skipped frames without stalling TCP ingestion.
3. **Mid-Frame Cancellation Safety**: [Connection tasks check for shutdown cancellation signals only *after* completing a full frame decode to prevent partial-frame stream corruption.](https://github.com/timyiu478/async-telemetry-ingestion-broker/blob/main/src/server.rs#L106-L110)
4. **Signal Propagation (`CancellationToken`)**:
   * *How*: Use `tokio_util::sync::CancellationToken` to notify all spawned tasks across the system.
   * *Why*: It is cheaply cloneable, thread-safe (`Send + Sync`), and implements `Future`, allowing seamless integration with `tokio::select!`.
5. **Draining & Task Synchronization (`TaskTracker`)**: Use [`tokio_util::task::TaskTracker`](https://tokio.rs/tokio/topics/shutdown#waiting-for-things-to-finish-shutting-down) to track active tasks, seal new spawns (`tracker.close()`), and await clean task execution drainage (`tracker.wait()`) during graceful shutdown.
6. **Resource Bounding via RAII**: Combine `Arc<Semaphore>` permits with task ownership so dropped TCP socket handlers automatically return permit capacity to the server pool.
7. Why the server cannot accept connections after `tracker.close()`? Because the TcpListener is destroyed before tracker.close() is ever called.

```text
[ Ctrl+C pressed ]
       │
       ▼
1. Background task wakes up and executes cancel.cancel()
       │
       ▼
2. Inside server::run, tokio::select! detects cancellation
   └─► Immediately drops `accept_loop` (TcpListener closed, port released)
   └─► `server::run` completes and returns Ok(())
       │
       ▼
3. server::run(...).await in main() FINALLY completes
       │
       ▼
4. main() advances to the next line: tracker.close()
       │
       ▼
5. main() advances to: tracker.wait().await
```
