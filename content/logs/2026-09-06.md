#### Rust Collection: Vector

```rust
fn main() {
  let mut v: Vec<i32> = vec![1, 2, 3];
  let mut v2: Vec<&mut i32> = Vec::new();
  for i in &mut v {
    v2.push(i);
  }
  *v2[0] = 5;
  let a = *v2[0];
  let b = v[0];
  println!("{a} {b}");
}
```

The above program will pass the compiler.

The expected output of the program: `5 5`

Memory Layout:

```
Stack | Heap

v ---------> [5, 2, 3]
v2 --------> [^, ^, ^] // ^: pointer to v
```

#### Rust Collection: String

* The difference between using a + b and a.push_str(b) to concatenate two strings: `a+b` will consume the ownership of `a` while `a.push_str(b) does not
* Why Rust strings don't support indexing:
    * Variable-Width Encoding: A String is a UTF-8 wrapper around `Vec<u8>`, where characters take 1 to 4 bytes. Direct byte-indexing could land in the middle of a multi-byte character, yielding invalid data or triggering a runtime panic.
    * Semantic Ambiguity: "Character" is ambiguous in Unicode. Indexing could refer to raw bytes (u8), Unicode scalar values (char), or human-perceived characters (grapheme clusters).
    * Performance Guarantees: The [] indexing operator implies `O(1)` constant-time access. Finding the `i`-th character in variable-length UTF-8 requires an `O(N)` linear scan; Rust refuses to hide `O(N)` operations behind `O(1)` syntax.
* The difference between the types of a string slice &str and a byte slice &[u8]: &str points to bytes that can always be interpreted as UTF-8, whereas &[u8] can be any byte sequence

#### Rust Ownership

```rust
fn reverse(v: &mut Vec<String>) {
    let n = v.len();
    for i in 0 .. n / 2 {
        let p1 = &mut v[i] as *mut String;
        let p2 = &mut v[n - i - 1] as *mut String;
        unsafe { std::ptr::swap_nonoverlapping(p1, p2, 1); }
    }
}
```

Why It Compiles?

* Temporary Borrowing: `&mut v[i]` creates a temporary mutable reference.
* Casting it (as `*mut String`) consumes the reference immediately, ending its lifetime at the semicolon.
* No Overlapping Borrows: Because the temporary borrow for p1 is dropped on line 4, `v` is unborrowed when `&mut v[n - i - 1]` is evaluated on line 5. At no point do two mutable references co-exist.
* Un-tracked Raw Pointers: `p1` and `p2` store raw pointers (`*mut String`), which carry no lifetimes and are not tracked by the borrow checker.
* Unsafe Boundary: The unsafe block satisfies the requirement for executing pointer-manipulating functions like `std::ptr::swap_nonoverlapping`.

Why It Is Safe? 

* Non-Overlapping Memory: The swap_nonoverlapping API requires that the memory regions of `p1` and `p2` do not overlap.
* Valid Allocation & Alignment: Both pointers point to valid, fully initialized String elements within v's allocated memory buffer and inherit proper memory alignment from `Vec<String>`.
