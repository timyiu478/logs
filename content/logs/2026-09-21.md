Arena / Bump Allocator:

* User-space abstraction built on top of raw memory (can be backed by OS heap pages OR thread stack memory).
* From the OS perspective, it is just raw virtual memory pages mapped to the process—the kernel has zero awareness of individual objects inside.
* Usage: Store short-lived objects with shared lifetimes (e.g., per-request, per-frame), bypassing thread-safe global allocator overhead (`malloc`/`free`).
* Key Trade-offs & Limitations:
    * No individual deallocation: Memory can only be freed all at once when the entire arena resets.
    * Unpredictable batch sizes: If a batch exceeds the pre-allocated arena capacity, you risk stack overflow (if stack-backed) or triggering an expensive re-allocation / chain-chunk allocation (if heap-backed).
